## 一、术语与寄存器速查

### PCIe 配置空间（每个设备都有）

| 偏移 | 名称 | 作用 |
|---|---|---|
| `cap+0x0C` | `LNKCAP` | **能力声明**：最大速率（`[3:0]`）+ 最大宽度（`[9:4]`） |
| `cap+0x10` | `LNKCTL` | 链路控制，`bit5` = Retrain Link |
| `cap+0x12` | `LNKSTA` | **当前状态**：当前速率（`[3:0]`）+ 当前宽度（`[9:4]`） |
| `cap+0x2C` | `LNKCAP2` | **支持速率向量**：`bit1`=2.5GT，`bit2`=5.0GT，`bit3`=8.0GT |
| `cap+0x30` | `LNKCTL2` | 目标速率 `TLS[3:0]`（1=2.5GT, 2=5.0GT, 3=8.0GT） |

`cap` 是 PCIe 能力结构的偏移，由配置空间 `0x34` 起的能力链找到（P104 上是 **`0x78`**）。

### PCIe 速率编码

| 值 | 速率 |
|---|---|
| 1 | 2.5 GT/s（Gen1） |
| 2 | 5.0 GT/s（Gen2） |
| 3 | 8.0 GT/s（Gen3） |
| 4 | 16 GT/s（Gen4） |

### P104 的 BAR0 寄存器（GPU 内部）

| 偏移 | 名称 | 作用 |
|---|---|---|
| `0x8841C` | `nv_pci.CONFIG` | `GEN2_DIS[12:11]`；置 bit11/13、清 bit12/14 = 允许 Gen2 |
| `0x88610` | `VSEC_HIERARCHY` | 清 `bit12`、置 `bit0` |
| `0x8872C` | `LTSSM / XVE_OVR` | 写 `6` |
| `0x8C040` | `PPCI_2.CONFIG_LINK` | **速率请求** `SPEED[19:18]`：**Pascal 编码 `0`=8GT / `1`=5GT / `2`=2.5GT**（★ 与 Ampere 相反！） |
| `0x8C080` | `PPCI_2.WIDTH` | 当前宽度（只读）。x1 时 `0x101`，x4 时 `0x404` |
| `0x88084` | `LNKCAP` 镜像 | 声明镜像（只读） |
| `0x880A4` | `LNKCAP2` 镜像 | 支持速率向量镜像（只读）—— **用它判断声明是否解锁** |
| `0x8E110/11C/120/12C` | `XP3G_OVR0/3, VAL0/3` | 写 `1 / 4 / 0 / 0x00200000` |

> ⚠️ **Pascal 的 `0x8C040` 速率编码与 Ampere 相反**。
> 照 Ampere（170HX）文档写 `2` 等于写 Gen1 —— 这个坑会浪费大量试错时间。

### BAR0 镜像区的偏移算法

BAR0 的 `0x88000` 区是 PCI 配置空间镜像，映射关系：

```
镜像偏移 = 0x88000 + 0x08 + (配置空间偏移 - 0x78) + 0x78
        = 0x88000 + 配置空间偏移 + 0x08
```

例：配置空间 `0xA4`（`LNKCAP2`）→ 镜像 `0x88000 + 0xA4 + 0x08 = 0x880AC`？
**不对** —— 实测 P104 的 `LNKCAP2` 镜像是 **`0x880A4`**，即 `0x88000 + 0xA4`。
`LNKCAP`（配置 `0x8C`）镜像 = `0x88084` = `0x88000 + 0x84` = `0x88000 + 0x8C - 8`。
**建议以实测为准，不要照搬公式。**

## 二、完整解锁配方

### 第 1 步：写使能位 + 速率请求

```
BAR0 0x8E110 = 0x00000001
BAR0 0x8E11C = 0x00000004
BAR0 0x8E120 = 0x00000000
BAR0 0x8E12C = 0x00200000

BAR0 0x8841C = (旧值 | (1<<11) | (1<<13)) & ~((1<<12) | (1<<14))
BAR0 0x88610 = (旧值 & ~(1<<12)) | 1
BAR0 0x8872C = 6

BAR0 0x8C040 = (旧值 & ~0x000C0000) | (1 << 18) | 1     ← SPEED=1(5GT) + COMMIT
```

**注意**：`0x8C040` 的 `bit0`（COMMIT）会被硬件**立即自清**。
这是正常的，不代表写入失败。持续补写是第 4 步的职责。

### 第 2 步：★★ 真正的整卡复位（决定成败）

```
1. SetupDiGetClassDevs(NULL, NULL, NULL, DIGCF_PRESENT | DIGCF_ALLCLASSES)
2. 枚举，找出 InstanceId 含 VEN_10DE & DEV_1B87 的【Present】实例
3. SetupDiSetClassInstallParams(set, &dev, {
       ClassInstallHeader.InstallFunction = DIF_PROPERTYCHANGE (0x12),
       StateChange = DICS_DISABLE (0x02),
       Scope = DICS_FLAG_GLOBAL (0x01)
   })
4. SetupDiCallClassInstaller(DIF_PROPERTYCHANGE, set, &dev)
5. 轮询 PCI 配置空间，直到读不到 0x1B8710DE（设备真的离开总线）
6. 同法执行 DICS_ENABLE (0x01)
7. 轮询，直到重新读到 0x1B8710DE
8. 重新读 BAR0（地址可能不变），重新映射 MMIO
```

**复位后应立即观察到：**

```
LNKCAP  = 0x00463C42   （原 0x00463C41）
LNKCAP2 = 0x00000006   （原 0x00000002）  ← 声明解锁
TLS     = 2
```

> ### 为什么不能用 `pnputil /restart-device`
>
> `pnputil /restart-device` 只重启**驱动栈**，**设备不离开总线**。
> 实测：命令成功、卡不掉线，但 `LNKCAP2` 仍为 `0x02`。
> 必须让设备真正离开总线再回来 —— 只有 SetupAPI 的 `DIF_PROPERTYCHANGE` 能做到。

### 第 3 步：两端 TLS + 交替重训

```
端点   LNKCTL2[3:0] = 2
根端口 LNKCTL2[3:0] = 2
根端口 LNKCTL[5]   = 1     （Retrain Link）
端点   LNKCTL[5]   = 1
```

实测：**一轮就能上 Gen2**（`LNKSTA = 0x00001042`）。
工具里做了最多 6 轮，并每轮复写使能位，以应对不同主板。

> 端点的 `LNKCTL[5]` 在**声明未解锁时是只读的**（写进去立刻自清）。
> 声明解锁后它才可写。这也是"必须先做第 2 步"的又一个佐证。

### 第 4 步：常驻按住循环

```
每 20ms：
    重写第 1 步的全部寄存器
    重写两端 TLS=2
    读 LNKSTA；若速率 < 2（掉回 Gen1）→ 立刻重训
每 1500 次：打印一次状态
MMIO 连续 20 次读到 0xFFFFFFFF → 重新装载驱动并重映射
```

**不可省。** 停止后链路会掉回 Gen1（实测 `0x00001042` → `0x00001041`）。

## 三、为什么"声明"是关键

PCIe 链路速率取**两端能力的较小值**：

```
实际速率 = min(端点声明的最高速率, 上游端口声明的最高速率)
```

在本例中：

| | 声明 | 实际 |
|---|---|---|
| 上游根端口 | 2.5 / 5 / 8 / 16 GT/s 全支持 | — |
| **P104 端点（复位前）** | **只声明 2.5 GT/s** | 链路 = **2.5 GT/s** |
| **P104 端点（复位后）** | **声明 2.5 + 5.0 GT/s** | 链路 = **5.0 GT/s** |

上游端口完全有能力，瓶颈只在**端点自己的声明**。
而声明是 PCIe 核在初始化时算出来并**锁存**的 —— 所以必须触发重新初始化。

## 四、必须避开的三个坑

### 坑 1：驱动策略 `RMPcieLinkSpeed = 2`

NVIDIA 驱动加载时会读显卡类键的 `RMPcieLinkSpeed`：

- `=1` → 允许 Gen2
- **`=2` → 把 GPU 的 `LNKCTL2` TLS 钳死在 Gen1**

症状：写 `TLS=2` 回读仍是 1、重训全败、`nvidia-smi` 永远显示 Gen1。

**本工具在解锁前会预检并自动改正。** 类键位置：

```
HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-e325-11ce-bfc1-08002be10318}\000X
（用 MatchingDeviceId 匹配 pci\ven_10de&dev_1b87 找到 X）
```

工具写的三条策略：

```
RMPcieLinkSpeed   = 1
RmForceEnableGen2 = 1
RmEnableGen2      = 1
```

⚠️ 用 `reg add` 处理带花括号的类键会报错，必须用 PowerShell 的 `New-ItemProperty`
或 `Microsoft.Win32.Registry` API（工具用的是后者）。

### 坑 2：设备实例的"幽灵记录"

设备换过插槽后，Windows 会保留旧实例记录（`Present = False`）。

```
PCI\VEN_10DE&DEV_1B87&...\4&6FD99BD&0&00EB   Present: False   ← 幽灵（旧的 x1 口）
PCI\VEN_10DE&DEV_1B87&...\4&BF82947&0&0008   Present: True    ← 当前（CPU x16 槽）
```

**必须只对 `Present = True` 的实例做禁用/启用**，否则：
- 枚举时会拿到多个/拼接的 ID → `Disable-PnpDevice` 报 `0x80041017`（无效查询）
- 禁用失败 → 后面的解锁全部无效

工具用 `DIGCF_PRESENT` 过滤，并只取枚举到的第一个。

### 坑 3：BAR0 MMIO 映射会泄漏

`ThrottleStop.sys` 的映射 IOCTL（`0x8000645C`）**每次调用都会泄漏一份内核映射**。
在高频循环里反复调用会累积上千次，最终导致该驱动实例失效（之后读回全 `0xFFFFFFFF`）。

**正确做法**：对每个物理页**只映射一次并缓存**（工具就是这么做的：
`_vaLink` / `_vaPpci` / `_vaXp3g` 三个页，启动时映射一次）。

如果映射真的失效了，工具会：卸载驱动 → 重新装载 → 重新映射（自愈）。

## 五、判据

**唯一可信的判据是这两条：**

1. **寄存器**：`LNKSTA` 的速率字段 = 2（5.0 GT/s），宽度 = 4
2. **实测带宽**：单向 H2D 从 0.78 GB/s 提升到 ~1.55 GB/s

**不要用的判据：**

| 判据 | 为什么不可靠 |
|---|---|
| `nvidia-smi` 的 `pcie.link.gen.current` | 读的是驱动侧缓存/省电态。实测寄存器是 Gen2 时它报 1 |
| GPU-Z 空闲时的显示 | 省电会降速到 Gen1，负载时才回升 |
| `LNKCAP` | 只表示"能力"，不表示"当前" |
| 按住进程的日志 | 日志说成功但链路可能已掉，要以 `LNKSTA` 为准 |

**带宽测量方法**（CUDA，单向分开测）：

```python
# 用 512MB 页锁定内存，H2D 和 D2H 分开计时，各跑 12 次取平均
# 预期：Gen1 x4 ≈ 0.78 GB/s，Gen2 x4 ≈ 1.55 GB/s
```

## 六、故障排查

| 症状 | 原因 | 解决 |
|---|---|---|
| `驱动加载失败：错误 1275` | 易受攻击驱动阻止列表开启 | 安全中心 → 设备安全性 → 内核隔离 → 关闭"阻止列表" → **重启** |
| `驱动加载失败：错误 31` | 反作弊预启动驱动（如腾讯 ACE-BOOT）拦截 | 临时停掉它；或改用别的机器 |
| `写通道自检失败` | 驱动加载了但 IOCTL 不通 | 换用包内的驱动文件；确认是管理员运行 |
| 禁用失败 `0x80041017` | 抓到幽灵实例 | 用 `DIGCF_PRESENT` 过滤（工具已处理）；或先重启清幽灵 |
| 复位后卡没回来 | 极少数主板不支持这种复位 | 重启机器即可恢复，不会损坏 |
| 复位后 `LNKCAP2` 仍是 `0x02` | 复位深度不够 | 确认用的是 `DIF_PROPERTYCHANGE`，不是 `pnputil` |
| `LNKCAP2` 变了但链路仍 Gen1 | 没有重训，或 `RMPcieLinkSpeed=2` | 检查 TLS=2；检查驱动策略 |
| 解锁后又掉回 Gen1 | 按住进程没在跑 | 重跑 `bin\P104Gen2x4.exe` |
| 读回全 `0xFFFFFFFF` | MMIO 映射失效 | 工具会自愈；或重启 |
| 间歇性掉回 Gen1 | 杀软/系统结束了按住进程 | 把工具目录加入杀软白名单 |

## 八、安全说明

**用到的两个内核驱动**（均随包提供，均为社区公开的 BYOVD 类驱动）：

| 驱动 | 用途 | 签名 |
|---|---|---|
| `WinRing0x64.sys` | 读写 PCI 配置空间（IOCTL `0x9C406144` 读 / `0x9C40A148` 写） | 有效 |
| `ThrottleStop.sys` | 映射物理页到应用层（IOCTL `0x8000645C`） | 有效（TechPowerUp LLC） |

两者以 `demand` 方式临时创建服务、用完即删，**不常驻**。
但按住进程运行期间需要保持加载。

**固有风险**：BYOVD 驱动本身是攻击面，加载它们等于降级系统防护。
**玩带反作弊的游戏前建议先卸载。**
