# 常见问题（FAQ）

---

## 基本问题

### Q1：这个工具到底做了什么？

把 P104-100 的 PCIe 链路从 **Gen1（2.5GT/s）提速到 Gen2（5.0GT/s）**，
CPU 与显存之间的数据搬运速度**翻倍**（0.78 → 1.55 GB/s）。

做法是通过软件重新触发显卡的 PCIe 初始化，让它重新"声明"自己支持 Gen2。
**不刷 VBIOS，不改硬件。**

### Q2：会不会把卡刷坏 / 变砖？

**不会。** 工具只做两件有影响的事：
1. 写 GPU 的运行时寄存器（断电即失，重启恢复）
2. 把设备禁用再启用一次（类似设备管理器里点"禁用设备"再"启用设备"）

**没有写任何 Flash / EEPROM。** 最坏情况是显卡从总线掉线，重启即恢复。

### Q3：会不会影响我的显示？

**不会。** P104-100 **没有显示输出接口**，它不承担显示任务。
禁用/启用它的时候屏幕不会黑。

（如果你把 P104 当主显示卡用——那不可能，它没有输出口。）

### Q4：安全吗？为什么需要加载内核驱动？

工具需要直接读写 GPU 的 BAR0 寄存器和 PCI 配置空间，
这在 Windows 应用层做不到，必须借助两个社区公开的内核驱动
（`WinRing0x64.sys` / `ThrottleStop.sys`，都带有效签名）。

驱动是**临时加载、用完即删**的，但按住进程运行期间需要保持加载。

⚠️ 这类驱动（BYOVD）本身是攻击面，**玩带反作弊的游戏前建议先卸载**。

## 使用问题

### Q5：装完为什么还是 Gen1？

按顺序检查：

1. 跑 `status.cmd`，看"按住进程是否在运行"
   - **未运行** → 链路必然掉回 Gen1。运行 `bin\P104Gen2x4.exe`
2. 看 `LNKCTL2` 是不是 TLS=2
   - 不是 → 解锁没成功，重跑 `-once` 看日志
3. 看 `LCAP2` 是不是 `0x06`
   - 是 `0x02` → **整卡复位那一步没生效**，检查是否有杀软拦截

### Q6：为什么 GPU-Z / nvidia-smi 显示 Gen1，但 status 说已解锁？

**这是本工具最容易被误解的地方，请读完这一节。**

#### 两种完全不同的情况

| 现象 | 是不是问题 |
|---|---|
| **GPU 空闲时**显示 Gen1，有负载时回到 Gen2 | ✅ 正常（省电降速） |
| **有负载时也一直**显示 Gen1，但 `status.cmd` 说 Gen2 | ⚠️ **不是故障 —— 是 GPU-Z/nvidia-smi 读错了** |

#### ★★ 为什么它们会读错

**GPU-Z 和 nvidia-smi 显示的不是 PCIe 寄存器，而是【NVIDIA 驱动上报的值】。**

在这张**无显示输出的矿卡**上，驱动上报值**不可靠**：

```
实测：寄存器 LNKSTA 说 5.0GT/s（Gen2），实测带宽 1.56 GB/s（Gen2）
      但 nvidia-smi 的 pcie.link.gen.current / gpucurrent 始终报 1
```

**⇒ 这是驱动的已知行为，不是卡坏了，也不是工具没生效。**

#### ★★★ 正确的判据（按可信度排序）

**1. 带宽实测（唯一不会骗人的）**

```
双击 bin\check-bw.cmd

参考值（x4 宽度）：
    Gen1 x4 = 约 0.78 GB/s
    Gen2 x4 = 约 1.55 GB/s    <- 目标
    Gen3 x4 = 约 3.10 GB/s
```

**2. `LNKSTA` 的原始值（status.cmd 现在会打印）**

```
端点   01:00.0  LNKSTA = 0x00001042   SPD[3:0]=2 (5.0GT/s)  WIDTH[9:4]=4
根端口 00:01.0  LNKSTA = 0x25807042   SPD[3:0]=2 (5.0GT/s)  WIDTH[9:4]=4
                                  ↑ 两端都必须是 2 才是真的 Gen2
```

**`LNKSTA` 是 PCIe 标准的"链路状态"寄存器，反映【当前已协商的速率】，可信。**

#### ⚠️ 绝对不要用来判断"当前速率"的字段

**这些是"能力声明"或"目标请求"，不是当前速率：**

| 字段 | 它其实是什么 |
|---|---|
| `LNKCAP[3:0]` | **能力上限**（"我最高能跑多少"） |
| `LNKCAP2[6:1]` | **支持速率向量**（"我支持哪几代"） |
| `LNKCTL2[3:0]` (TLS) | **目标速率请求**（"我希望跑多少"） |
| `nvidia-smi` 的 `pcie.link.gen.*` | **驱动缓存值**，本卡不可靠 |
| GPU-Z 的 "Bus Interface" 主显示 | 同上，来自驱动 |

> **历史教训**：本项目的开发者曾因为用 `LNKCAP2` 当判据，
> **三次误报"Gen3 成功"**。所以这条规则写得很重。

#### 想空闲也不掉速

```
powercfg -setacvalueindex SCHEME_CURRENT SUB_PCIEXPRESS ASPM 0
powercfg -setdcvalueindex SCHEME_CURRENT SUB_PCIEXPRESS ASPM 0
powercfg -setactive SCHEME_CURRENT
```

**⚠️ 注意：改完之后 `status.cmd` 的结论仍然以 `LNKSTA` + 带宽为准，
GPU-Z 该显示 Gen1 还是会显示 Gen1（因为它读驱动值）。这不是没生效。**

### Q7：装了之后显卡游戏性能会变好吗？

带宽翻倍对**需要频繁在 CPU 和显存之间搬数据的场景**有帮助：
- AI 推理 / 出图（模型加载更快，但推理速度主要受显存带宽限制）
- 数据预处理密集的训练
- 视频处理

对**纯游戏**帮助有限（P104 没有视频输出，本来也不适合玩游戏）。
真正受益的是**计算任务**。

### Q8：怎么彻底卸载 / 恢复原状？

```
右键 bin\uninstall.cmd → 以管理员身份运行 → 重启
```

会：删除计划任务、卸载两个内核驱动、清除驱动策略、还原寄存器、删除安装目录。
**显卡回到出厂状态。**

### Q9：每次开机都要手动运行吗？

不用。安装时会注册一个开机自启的计划任务
（`P104 PCIe Gen2x4 Bring-up`，SYSTEM 权限，开机 30 秒后执行）。
开机后约 **2-4 分钟**自动解锁，无需操作。冷启动时可能需要几次整卡复位，属正常现象 —— 期间请勿手动反复运行工具。

### Q10：按住进程能关掉吗？关掉会怎样？

能关（任务管理器结束 `P104Gen2x4.exe`），但**链路会在几秒内掉回 Gen1**。

这是正常的 —— NVIDIA 驱动会持续把链路策略往回压，
必须有一个常驻进程和它对写。这也是同类工具都需要"看门狗"的原因。

## 技术问题

### Q11：为什么必须"禁用再启用"？`pnputil /restart-device` 不行吗？

**不行，这是整个破解的关键。**

| 方式 | 设备是否离开总线 | 能否让声明变成 Gen2 |
|---|---|---|
| `pnputil /restart-device` | ❌ 否（只重启驱动栈） | ❌ 试过，`LCAP2` 仍是 `0x02` |
| **`Disable-PnpDevice` → `Enable-PnpDevice`** | ✅ **是** | ✅ **`LCAP2` 变成 `0x06`** |

显卡的"支持速率声明"是 PCIe 核在**设备初始化**时算出来并锁存的。
只有让设备真正从总线上消失再回来，这个初始化才会重跑。

详见 [研究过程记录.md](../研究过程记录.md) 第七节。

### Q12：为什么必须常驻"按住"？

NVIDIA 驱动会持续把链路配置往回压（把速率请求改回 Gen1）。
必须有一个进程持续补写，否则链路会掉回去。

实测：按住时 2043/2043 次采样全是 Gen2（100%）；
一旦停止，几秒内掉回 Gen1。

### Q13：`0x8C040` 的 COMMIT 位为什么写完就变 0？

**硬件自清，正常。** 那个位是"触发"语义，写完立刻归零。
所以判断"要不要补写"不能只看这个位——否则每一轮都会判定需要补写
（前人的记录里 `1910 检查 / 1910 补写` 的 1:1 比例就是这么来的，
不是"驱动在回写"）。

### Q14：为什么 Gen3 不行？

因为 **P104 自己声明的上限就是 Gen2**（`LNKCAP2` 的 8GT 位写进去被硬件拒绝）。

同族的 CMP 40HX（Turing TU106，芯片原生 Gen3）也只声明到 Gen2。
所以这是 GPU 的 PCIe 核配置，不是主板或驱动的问题。

### Q15：为什么宽度只能是 x4？

一层层看：

1. **卡的声明**：`LNKCAP` 的宽度字段固定为 4，只读。
2. **物理**：P104 的 PCB 只有 4 条 lane 做了端接，
   其余金手指被胶带封住、背面 AC 耦合电容未焊。
3. **端口**：本机测试槽是 x4 电气。

要让宽度变成 x16，需要**同时**：
- 改声明的宽度字段（需要刷改过的 VBIOS，补丁已备好但未验证）
- 补 12 对 AC 耦合电容（100nF X7R ≥16V）
- 撕掉金手指胶带

**注意顺序**：必须先在能跑 Gen2 的状态下补电容，
否则多出来的 lane 没有耦合会导致链路训练失败。

### Q16：能在别的 P104-100 上用吗？

**理论上可以**，因为改的是通用寄存器（不是卡特有的）。
但**未在其他卡上验证过**，不同批次/品牌的 PCB 可能不同。

如果你试成功了（或失败了），欢迎反馈读数。

### Q17：P106-100 / P102 / CMP 系列能用吗？

**不要直接套用。**

- 设备 ID 不同（工具硬编码 `10DE:1B87`）
- 不同架构的寄存器编码不同
  （例如 `0x8C040` 的速率编码，**Pascal 与 Ampere 相反**）
- CMP 系列（如 40HX）本来就声明 Gen2，用不上这个工具

原理可能相通，但需要重新验证寄存器。

### Q18：会不会影响同一台机器上的其他显卡？

不会。工具只操作 `10DE:1B87` 这一个设备。
**建议先确认你的设备 ID** 再运行（`status.cmd` 会打印）。

### Q19：日志在哪？

```
C:\ProgramData\P104Gen2x4\status.txt
```

### Q20：能自己改源码吗？

能，源码在 `src\P104Gen2x4.cs`，用系统自带的 .NET Framework 编译器即可重编译

## 出问题时

### Q21：报错 `驱动加载失败：错误 1275`

Windows 的"易受攻击的驱动程序阻止列表"开着。

**解决**：Windows 安全中心 → 设备安全性 → 内核隔离 → 关闭"Microsoft 易受攻击的驱动程序阻止列表" → **重启**。

### Q22：报错 `驱动加载失败：错误 31`

被反作弊的**预启动内核驱动**拦截了（常见元凶：腾讯 ACE 的 `ACE-BOOT.sys`）。
它在**驱动映像加载阶段**就拦截，重装/重启都无效。

**解决**：临时停掉它（`sc stop ACE-BOOT` 或 `sc config ACE-BOOT start= demand`），
解锁完成后恢复。或者换一台没有反作弊的机器。

### Q23：卡从总线上消失了

极少数主板在这种复位下会掉卡。

**解决**：**重启机器**。不会造成物理损坏。
重启后卡会正常枚举（只是回到 Gen1 状态）。

### Q24：`status.cmd` 说按住进程在跑，但我觉得没效果

**别猜，用两个硬判据核对：**

**判据 1 —— `status.cmd` 里的 `LNKSTA` 原始值**

```
端点   01:00.0  LNKSTA = 0x00001042   SPD[3:0]=2 (5.0GT/s)
根端口 00:01.0  LNKSTA = 0x25807042   SPD[3:0]=2 (5.0GT/s)
                                  ↑ 是 2 就是 Gen2；是 1 就是没上去
```

**判据 2 —— 带宽实测**

```
双击 bin\check-bw.cmd
   H2D ≈ 1.55 GB/s  ⇒  Gen2 x4（正常）
   H2D ≈ 0.78 GB/s  ⇒  Gen1 x4（没上去）
```

**如果 `LNKSTA` 是 2 且带宽是 1.55，但 GPU-Z 显示 Gen1
⇒ 那是 GPU-Z 读驱动值的问题，不是工具没生效（见 Q6）。**

### Q25：解锁成功过，后来突然又变 Gen1 了

可能原因：
- 按住进程被结束（杀软、任务管理器、系统更新）
- MMIO 映射失效（驱动实例被回收）

**解决**：重跑 `bin\P104Gen2x4.exe`。如果频繁发生，
把工具目录加入杀软白名单，并检查计划任务是否还在。
