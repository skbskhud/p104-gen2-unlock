# 工具说明：P104-100 Gen2 x4 解锁工具

> 解锁工具以**独立发布包**形式提供（目录/压缩包名以发布版为准）。
> 本文是使用说明与排错手册；下文中的 `P104-Gen2x4-组合包/` 指该发布包解压后的目录，
> **具体文件布局可能随版本微调**。工具的完整技术文档（含源码逐段说明）见发布包内的
> `README.md` 与 `docs/技术细节.md`。

---

## 1. 这个工具做什么

**把 NVIDIA P104-100 的 PCIe 链路从 Gen1（2.5 GT/s）提到 Gen2（5.0 GT/s）。**
在 x4 宽度下，CPU↔显存单向带宽约翻倍：

```
Gen1 x4：H2D 0.78 GB/s   D2H 0.84 GB/s
Gen2 x4：H2D 1.55 GB/s   D2H 1.69 GB/s
```

### 它做什么

1. 通过两个内核驱动读写 GPU 的 BAR0 寄存器与 PCI 配置空间（**只针对 `10DE:1B87` 这一个设备**）
2. 把 P104 通过 PnP **禁用一次、再启用一次**（等价于在设备管理器里点"禁用设备"再"启用设备"）
3. 往显卡类注册表键写策略值（`RMPcieLinkSpeed` 等，与 NVIDIA 驱动的策略同名）
4. 启动一个常驻进程，每 ~20 ms 重写相关寄存器（**"按住"是必需的**，否则会掉回 Gen1）
5. 注册一个开机自启的计划任务（名 `P104 PCIe Gen2x4 Bring-up`）

### 它不做什么

| 不做 | 说明 |
|---|---|
| ❌ 不刷 VBIOS / EEPROM / Flash | 全程没有任何固件写入 |
| ❌ 不改硬件 / 不焊接 | 纯软件 |
| ❌ 不联网 | 无网络行为 |
| ❌ 不碰其他设备 | 只匹配 `10DE:1B87` |
| ❌ 不常驻驱动 | 按住进程之外的驱动/服务在退出时移除 |
| ❌ 不需要魔改驱动 | 官方 NVIDIA 驱动即可 |

**没有写任何 Flash/EEPROM。** 寄存器写入断电即失，`uninstall.cmd` + 重启可完全还原。

## 3. 前置条件

| 项目 | 条件 |
|---|---|
| 系统 | Windows 10 / 11（64 位） |
| 权限 | `install.cmd` / `uninstall.cmd` 需**管理员**；`status.cmd` 不需要 |
| 硬件 | NVIDIA P104-100（`10DE:1B87`），本项目只在 CPU 直连插槽验证过 |
| 显卡驱动 | 任意可用的官方 NVIDIA 驱动（无需魔改） |
| 安全设置 | 需关闭 **"Microsoft 易受攻击的驱动程序阻止列表"**，关闭后**必须重启** |
| 杀毒软件 | 会报警，**这是预期行为**（见第 6 节） |

### 关闭"易受攻击的驱动程序阻止列表"

```
Windows 安全中心 → 设备安全性 → 内核隔离
  → 找到「Microsoft 易受攻击的驱动程序阻止列表」→ 关闭
  → 【重启电脑】（必须重启才生效）
```

## 4. 快速开始

```bat
:: 1) 安装（管理员）
::    会把文件部署到 C:\Program Files\P104Gen2x4\，并立刻执行一次解锁
install.cmd

:: 2) 重启（推荐）
::    重启后约 30 秒自动完成解锁

:: 3) 查看状态（不需要管理员）
status.cmd
::    → 会打印原始寄存器值 + 带宽判定所需的证据

:: 4) 验证带宽（判据）
check-bw.cmd
::    → Gen1 x4 ≈ 0.78 GB/s   Gen2 x4 ≈ 1.55 GB/s
```

**成功判据（两个都要看）**：

1. `status.cmd` 里 `LNKSTA` 的速率字段 = **2**（表示 5.0 GT/s）；
2. `check-bw.cmd` 的 H2D ≈ **1.55 GB/s**。

> 只看带宽也可以 —— 它是唯一诚实的判据。理由见第 5 节。

## 5. ★ 为什么 GPU-Z / nvidia-smi 显示 "1.1 x4"（这不是故障）

这是本项目收到最多的疑问。答案：

**在 P104-100 上，`nvidia-smi` 与 GPU-Z 的"PCIe 代际"字段读的是 NVIDIA 驱动的报告值，
而这张矿卡的驱动报告值不可靠 —— 它始终报 Gen1。**

所以：

| 来源 | 是否可信 | 说明 |
|---|---|---|
| `status.cmd` 里的 **`LNKSTA` 原始值** | ✅ 可信 | 直接读 PCIe 链路状态寄存器，`SPD[3:0]`=2 即 5.0 GT/s |
| **带宽实测**（`check-bw.cmd` / GPU-Z 的 Bus Interface 带宽测试） | ✅ 最可信 | 物理量测，无法伪造 |
| `nvidia-smi` 的 `pcie.link.gen.*` | ❌ 不可信 | 报的是驱动缓存值 |
| GPU-Z 的 "Bus Interface" 代际文字 | ❌ 不可信 | 同上 |
| `LNKCAP` / `LNKCAP2` | ❌ 不可作速率判据 | 那是**声称的能力**，不是当前速率 |

**GPU-Z 的 Bus Interface 旁边的 `[?]` 按钮会跑真实带宽测试 —— 那个结果是可信的。**

## 6. 杀毒软件报警（预期行为，先读这一节）

### 现象

- 解压后弹 Windows 安全中心告警，标记为 **HackTool / Hacktool:Win64/WinRing0** 或 **RiskWare**；
- 有的杀软会直接删除 `.sys` 文件或整个压缩包；
- 运行时驱动加载失败：**错误 1275** 或 **错误 31**。

### 原因

工具需要直接读写 GPU 的 BAR0 与 PCI 配置空间，Windows 的应用层做不到，
必须借助两个**公开的、带有效数字签名的**内核驱动：

```
bin\drivers\WinRing0x64.sys
bin\drivers\ThrottleStop.sys
```

这两个驱动是社区通用工具（多个显卡解锁项目都在用），但这类驱动在安全界被称为
**BYOVD**（Bring Your Own Vulnerable Driver），可被恶意利用，所以杀毒软件一律标记它们
——**不管用在哪、用得多正当**。

### 处理

| 情况 | 处理 |
|---|---|
| 只是解压/下载报警 | 允许 / 保留文件即可 |
| 文件被删了 | 关闭杀软实时防护（或把目录加白名单），重新解压 |
| 运行报 **错误 1275** | 关"易受攻击的驱动程序阻止列表" → **重启** → 重跑 `install.cmd` |
| 运行报 **错误 31** | 被反作弊预启动驱动拦截（如腾讯 `ACE-BOOT`）。停掉它，或换机器 |

### 自行审阅

**全部代码在 `src\P104Gen2x4.cs`，是纯文本，可逐行审阅。**
它只做第 1 节列出的那几件事，不联网、不写固件、不碰其他设备。

⚠️ 玩带反作弊的游戏前建议先 `uninstall.cmd`（不是因为工具有害，而是因为 BYOVD 驱动本身是攻击面）。

## 7. 排错清单

| 症状 | 可能原因 | 处理 |
|---|---|---|
| `install.cmd` 说需要管理员 | 没有以管理员身份运行 | 右键 → 以管理员身份运行 |
| 运行后 `status.cmd` 仍显示 Gen1 | ① 还没重启；② 常驻进程没起来；③ 等的时间不够（需 ~25-30 秒） | 重启 → 等 30 秒 → 再 `status.cmd` |
| 状态文件不存在 / 内容很旧 | 常驻进程未运行或已退出 | 重跑 `install.cmd`；或看 `C:\ProgramData\P104Gen2x4\status.txt` |
| 状态显示 Gen2 但带宽只有 0.78 | 链路只是"声明"变了，实际没重训 | 重跑 `install.cmd`（它会重做整卡复位与重训） |
| 报 `MMIO 映射失败` | 另一个同类工具/服务占住了固定设备名 `\\.\WinRing0_1_2_0` | 用 `sc.exe stop` / `sc.exe delete` 清掉旧的同名服务后重试 |
| 开机黑屏 / 显示异常 | 极少数平台在 PnP 复位时机上不稳定 | 进安全模式运行 `uninstall.cmd`；或先禁用计划任务再排查 |
| `uninstall.cmd` 后仍显示 Gen2 | 寄存器有残留 | **重启**（寄存器是运行时的，重启必定恢复） |
| 带宽测试报 Python 相关错误 | 机器上没有可用的 Python | 用 GPU-Z 的 `[?]` 带宽测试代替（`check-bw.cmd` 里也有提示） |

## 8. 主程序的命令行模式（进阶）

熟悉命令行的话可直接调用 `bin\P104Gen2x4.exe`：

| 模式 | 作用 | 需管理员 |
|---|---|---|
| `-install` | 部署文件、注册开机自启计划任务 | ✅ |
| `-once` | 执行一次完整解锁（写请求 → PnP 复位 → 等锁存 → 重训） | ✅ |
| `-status` | 打印状态与原始寄存器值（读实时状态文件） | ❌ |
| `-diag` | 打印寄存器级诊断信息 | ✅ |
| `-off` | 还原 GPU 寄存器到默认值 | ✅ |
| `-uninstall` | 移除计划任务、驱动、注册表策略 | ✅ |
| `-vbios` | 读取 VBIOS 并算 MD5（**只读，不刷写**） | ✅ |
| （无参数） | 常驻"按住"模式（由计划任务在开机时启动） | — |

**状态文件位置**：

```
C:\ProgramData\P104Gen2x4\status.txt       完整日志（含历史）
C:\ProgramData\P104Gen2x4\当前状态.txt      实时状态（status.cmd 读它）
```

## 9. 完全卸载与还原

```bat
:: 管理员身份运行
uninstall.cmd
:: 然后重启
```

`uninstall.cmd` 会依次：结束常驻进程 → 移除计划任务/驱动/注册表策略 → 还原 GPU 寄存器 →
删除 `C:\Program Files\P104Gen2x4` 与 `C:\ProgramData\P104Gen2x4`。

> **说明**：卸载脚本会**强制结束**常驻进程（`taskkill /F`）。这是卸载路径的正常做法；
> 但在做寄存器实验时**不要**这样做（会让驱动进入不可恢复状态，重启才能恢复）。
> 两者场景不同，不要混淆。

还原后卡片回到出厂的 Gen1 x4，与使用工具前完全一致。

## 10. 安全边界（务必知悉）

1. **工具只对 `10DE:1B87` 生效**，其他设备一律不碰。
2. **不写固件**，所有写入断电即失。
3. **最坏情况是显卡从 PCIe 总线掉线**（历史测试中出现过），重启即可恢复 —— 本项目的实测记录里
   没有出现过需要重装系统或损坏硬件的情况。
4. **以下操作本项目明确不建议**（原因见技术报告）：
   - 为追求 Gen3 而刷写 VBIOS / EEPROM；
   - 为追求 x16 而焊接交流耦合电容；
   - 对 `0x8C040`（`LINK_CONFIG_0`）做逐位写走查 ——
     本项目曾因此让显卡掉下 PCIe 总线（详见 [`04-硬件事实表.md`](04-硬件事实表.md) 的"危险操作清单"）。
5. 本项目只在一张 P104-100 与一个平台上验证，**换平台/换卡不保证结论成立**。

## 开机后多久生效？

**约 2-4 分钟**（实测冷启动 3 分 26 秒）。

冷启动后 GPU 与驱动需要一段时间才能完成初始化；在此期间工具会自动重试，
**请不要手动反复运行**，否则会干扰它自己的重试节奏。

判断是否成功的唯一依据：`status.cmd` 里的 `LNKSTA` 显示 `0x...1042`
（末四位 `1042` = Gen2 x4），或 `check-bw.cmd` 实测 ≈ 1.55 GB/s。
