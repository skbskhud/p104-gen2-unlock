======================================================================
矿卡破解边界报告
======================================================================


----------------------------------------------------------------------
—— 哪些能解、哪些不能解、以及"为什么"
----------------------------------------------------------------------

English | 中文

这份报告整理自对两张 NVIDIA 矿卡（P104-100 / CMP 40HX）的完整实测。
目的不是提供一个"破解工具"，而是画一张边界地图：
哪些功能可以被主机侧手段解锁，哪些已经被封在改不动的那一层，
以及判断一张新卡值不值得投入时间的方法。

所有结论标注证据强度，所有失败路径如实保留。


----------------------------------------------------------------------
一、这份报告回答什么问题
----------------------------------------------------------------------

矿卡圈每天都在问同一类问题：

- "这张矿卡能不能解锁 Gen3？"
- "编解码器能不能开？"
- "显示输出能不能点亮？"
- "光追是不是被砍了？"

绝大多数回答是猜测、传闻，或者"某个论坛说可以"。

这份报告给出的，是有实测数据支撑的答案，以及更重要的：

每一条"不能"，究竟卡在哪一层，以及那一层能不能动。

----------------------------------------------------------------------
三、逐项说明
----------------------------------------------------------------------


3.1 P104-100：为什么 Gen2 能解，Gen3 不能


Gen2 能解的原因： 限制发生在寄存器层。驱动/固件在设备初始化时会根据一组输入
（PRIV 位、PUNITS 位、LTSSM 覆盖寄存器）生成"声明支持哪些速率"。
这组输入中，有两个是主机可以改的 ⇒ 改完 + 一次整卡复位 ⇒ 声明变成 Gen2，链路训练跟上。

Gen3 不能解的原因： 声明生成器只有两档输入（2.5 GT/s / 5.0 GT/s），
而"是否允许第三档"由一次性可编程熔丝 GEN3_DIS=1 直接决定。
三条独立证据：

1. 熔丝区可完整读取（fuse 命名空间映射已验证），GEN3_DIS 读为 1；全 700 点读数恒定，
   对主机写入免疫（同时刻对照写入成功 ⇒ 排除"工具坏了"）。
2. 声明寄存器 LNKCAP2 被标记为 R-EVF：任何特权级都没有写端口。
3. 穷举四条声明路径的全部组合（AND 门矩阵）：只有 2 档可能，没有组合能产出 Gen3。
4. 端点会立刻把目标速率钳回 Gen2（数千次尝试，0 成功）。
5. 社区同型项目（CMP 170HX）同样从未成功过。

⇒ "Gen3 不是还没找到方法，而是设备自己拒绝。"


3.2 P104-100：宽度为什么不能改


- 端点声明的最大宽度就是 x4（固件/熔丝决定）
- 链路宽度 = min(两端声明) ⇒ 上游是 x16 也没用
- 试图在 UEFI 阶段写宽度寄存器：驱动加载前就不可写
- 结论：不要为此焊接电容 —— 那解决的是电气连接，不是声明上限


3.3 P104-100：编解码器为什么不能开


- 媒体引擎是 Falcon 微控制器，其 MMIO 窗口返回 poison 值（"存在但被门控"）
- Falcon 的启动需要写一个只读寄存器，且代码/数据端口只读
- 驱动侧的唯一条件是软件对象字段，不是熔丝/注册表
- MISC_DISABLE 类掩码在 GP104 上根本不存在（全部 variants="GF100:GM107"）
- 结论：硬件在、驱动路径在，但被固件/熔丝层挡住


3.4 CMP 40HX：光追为什么不可解


先说结论的层次： "能不能开"和"是不是硬件加速"是两件事。

- 能开：驱动给出 DXR Tier 1.0（软件光追回退），游戏里选项可勾、画面有效果
- 不能硬件加速：系统只报 DXR Tier 1.0，而正常 RTX 20 系应为 Tier 1.1

证据：

  证据  数据
  DXR tier（第三方工具 dxr_info 独立查询）  40HX = 10（Tier 1.0）；同机 WARP = 11；Intel 核显 = 0
  3DMark Port Royal 光追分  2387（同芯片硬件光追期望 3800–4300，约 55%）
  光栅性能（Time Spy Graphics）  8487（正常甚至略超，说明整卡没被限频）
  换驱动复测  595.76 与 566.36 两个驱动分支：tier 都是 10，PortRoyal 2381 / 2387（差 0.25%）
  EFI 逆向  解锁 EFI 的全部 115 处寄存器写中，0 处涉及 RT / 显示
  熔丝区扫描  无任何可读的"RT 使能"熔丝，也没有可写开关

⇒ 光栅满血、光追腰斩 ⇒ 问题只在 RT 路径上，且不是"改寄存器"能修的。

关键澄清：GetRaytracingAccelerationStructurePrebuildInfo 返回真实显存尺寸，
只能证明加速结构接口是活的（CPU 侧尺寸计算），不能证明硬件光追遍历在执行。
判定硬件光追是否真在，必须看 DXR Tier + 真实 RT 负载吞吐，两者都要。


3.5 CMP 40HX：显示输出为什么不可解


这是这份报告里挖得最深的一条。 显示初始化不是"被某个条件跳过"，而是四层独立封死：

  层  证据  结论
  ① DevInit 反汇编  40HX 的 DevInit 共 934 条寄存器写：0 条落在显示窗口 0x6xxxxx、0 个显示类操作码（TMDS/CR/AUXCH）。对照同代显示卡 GTX 1070 / P4000M：11 条显示写 + 2 个 ZM_CR，且从 script[0] 可达  显示初始化不在执行路径上
  ② 显示钩子被摘  cond#85 @0x4A98 = (R[0x021C04]&1)==0 → SUB 0x765B，而 0x765B 只有 1 字节 0x71（DONE）。有 11 处调用点指向它  钩子被重定向到空脚本
  ③ 代码保留但未挂接  ROM 0x523E–0x670D 存在整棵显示初始化脚本树（>30 个脚本、约 119 条 0x6xxxxx 写，例：0x523E: 6e 00 c2 61 40… → R[0x61C200]），但 30 个入口的 SUB/JUMP/u32 外部引用扫描 = 0  死代码
  ④ 硬件/固件声明  DCB 表 @0x53AC ver0x41 cnt=0（GTX 1070 = 16）；PCIR class @0x170 = 0x030200（3D controller），实卡配置空间一致；PFUSE 0x021C04 = 0x00000001（nouveau 中 gm107_devinit_disable bit0 → disable DISP；NVIDIA 补丁称 NV_FUSE_STATUS_OPT_DISPLAY）  固件 + 熔丝层就是"无显示头"配置

对照验证： 挖矿的 P104-100 完全同型（其显示初始化代码 0x84DF/0x85FF 同样无人调用）。
⇒ 这是 NVIDIA 对挖矿 SKU 的既定做法，不是个例。

⇒ 靠打 VBIOS 补丁点亮显示器的期望值极低：要同时补 DCB、接回显示树、改 class，
而最后一层是硬件熔丝，主机侧不可改。


----------------------------------------------------------------------
四、为什么会有"能解"与"不能解"的分层
----------------------------------------------------------------------

把上面所有结论归纳一下，限制一般落在四层，从上到下越来越难：

  层  能改吗  典型表现  例子
  ① 寄存器层  ✅ 能改（需一次复位/重新初始化）  改完声明/目标值就生效  P104 Gen2、40HX Gen2
  ② 驱动层  ⚠️ 部分能（改注册表/INF 策略）  驱动的软件开关  P104 的 RMPcieLinkSpeed
  ③ 固件层（VBIOS / UEFI EFI）  ⚠️ 能改但有风险（补丁/重定向）  初始化序列被跳过、钩子被摘  40HX 算力解锁（EFI 写寄存器）
  ④ 熔丝层（硬件）  ❌ 基本不能（OTP，主机无写路径）  能力声明上限、单元禁用、无显示头  P104 Gen3、40HX 显示/RT

判断一条限制在哪一层，是本报告最有价值的部分。


----------------------------------------------------------------------
五、怎么判断一张新矿卡值不值得攻（方法）
----------------------------------------------------------------------

按顺序做，任何一步出现"熔丝层"证据，就可以停手了：


第 1 步：读能力声明（10 分钟）


· PCIe 配置空间的 LNKCAP / LNKCAP2 / LNKSTA
  → 声明的是几档速率、什么宽度
· 如果声明上限 = 实际值 ⇒ 看它是否由熔丝决定（第 3 步）
· 如果声明上限 > 实际值 ⇒ 只是"没谈上去"，大概率寄存器层可解 ✅


第 2 步：查有没有可改的输入（半天）


· 找"声明生成器"或"目标速率请求"寄存器
· ★ 必须做【对照写入】：证明"同一时刻写别的寄存器能写进去"
  ⇒ 否则"写不进去"这个结论无效（这个错误会让人白跑几天）


第 3 步：读熔丝（1 小时，需要 BYOVD 只读通道）


· 读熔丝区，找 GEN3_DIS / 单元禁用位 / 显示状态位
· ★ 同时验证：熔丝区可读 + 对照读取成功（否则"读不到"不等于"没有"）
· ★ 如果关键位 = 1 且是 OTP ⇒ 停手，这一层动不了


第 4 步：固件逆向（1–3 天）


· VBIOS DevInit / UEFI EFI 里找"初始化是否被跳过"
· ★ 注意区分三种情况：
  a) 代码在且可达 → 只是条件不满足 ⇒ 可能可解
  b) 代码在但不可达（死代码/钩子被重定向到空）→ 摘线，可补但风险高
  c) 代码根本不存在 → 初始化在更上层（PMU/驱动/RM）⇒ 换方向


第 5 步：算期望值


· 如果已经到了熔丝层 ⇒ 期望值接近 0，不值得再投入
· 如果卡在寄存器/驱动层 ⇒ 值得试，通常 1–2 天出结果

六、证据强度约定
----------------------------------------------------------------------

本报告统一使用五级标注，不允许混着说：

  标注  含义
  【实测】  有可重复的硬件读数或基准测试支撑；给出原始值
  【强支持】  多条独立证据指向同一结论，但没有单点决定性实验
  【推测】  有推理链，但缺少直接证据；明确标注为推测
  【未验证】  没做，或做了但结果不可解释
  【已否证】  曾被当作结论，后来被实验或更好的分析推翻

七、方法学教训（也许比结论更有价值）
----------------------------------------------------------------------

1. 判据只能用"当前状态"。 用"能力声明"寄存器做速率判据，曾导致三次误报成功。
2. 阴性结论必须配对照写入。 证明"写不进去"之前，必须先证明"同一时刻写别的寄存器能写进去"。
   缺了这一步，两条结论被迫作废。
3. 穷举 > 抽样；穷举必须记录并控制基线状态。 用错误的基线做过一次实验，结论整条作废。
4. "同值不同果"是隐藏变量的报警器。 同一个写操作在不同时间得到不同结果，一定存在未识别的状态变量。
5. API 声明 ≠ 硬件能力。 DXR Tier 1.0 是"驱动声明"，不能证明 RT 单元存在；
   加速结构 PrebuildInfo 有返回值也只是 CPU 侧尺寸计算。要证明硬件在执行，必须看真实负载吞吐。
6. "能开"和"有硬件加速"是两件事。 软光追能开、能跑、画面有效果，但性能只有硬件 RT 的约一半。
7. 主动交代覆盖边界。 寄存器扫描只覆盖设备向主机开放的那一部分。
   "没找到"和"扫过了"是两句话。
8. 多 agent 并行操作同一硬件必须记账"谁在何时动了机器"。 否则实验互相污染。


----------------------------------------------------------------------
八、覆盖边界
----------------------------------------------------------------------

- 本报告的硬件结论只针对：P104-100（GP104，10DE:1B87）、
  CMP 40HX（TU106，10DE:1F0B），以及同平台（Intel HM570 改板 / Windows 11）。
- 换平台、换卡、换驱动版本后结论可能不同。
- 寄存器扫描只覆盖设备向主机开放的部分（P104 上约 23.5% 的 dword 可读；
  按"整页全可读"的严格口径只有 1.9%）。
- 40HX 的显示/光追判定中，"机制层"（究竟是熔丝还是驱动策略）在无同 die 显示卡对照时
  只能做到"效果确证 + 机制无法判定"。本报告如实区分了这两者。


----------------------------------------------------------------------
九、一句话总结
----------------------------------------------------------------------

矿卡能不能解锁，取决于那道锁挂在哪一层。

寄存器层：一两天能解。固件层：能解但要冒险。
熔丝层：主机侧无解 —— 而大部分"被砍得很彻底"的功能，都挂在熔丝层。

所以真正省时间的做法不是"试"，而是先判断锁在哪一层。
