
硬件事实表：寄存器、熔丝、实测值速查
==================

本表是本项目所有实测数据的汇总。位域来源：envytools rnndb（_scratch/refs/*.xml）与 PCIe 规范；
数值来源：本卡实测。每条都标明是"实测值"还是"文档定义"。

约定：BAR0 偏移指从 0x50000000 起的字节偏移；配置空间偏移指 PCIe 配置空间字节偏移。
本卡的 BAR0 前 64 KB 与配置空间是 1:1 影子关系：BAR0[0x88000 + N] ≡ 配置空间[N]（已实测 19/19 一致）。

2. PCIe 配置空间寄存器（本卡实测）
---------------------

2.1 能力结构定位

配置空间 0x34 (CAP_PTR) = 0x60 → 能力链表起点
  0x60  PM 能力
  0x78  PCIe 能力结构  ← 本项目关注的全部字段都在这里
       0x78 = EXP_HEAD       (能力头)
       0x7C = EXP_DEV_CAP    (设备能力)
       0x80 = EXP_DEV_CMD_STA(设备控制/状态)
       0x84 = EXP_LNK_CAP    (链路能力)   ← 最大速率/宽度声明
       0x88 = EXP_LNK_CMD_STA(链路控制 + 链路状态) ← 当前速率/宽度
       0x8C = SLOT_CAP
       0x9C = DEV_CAP2
       0xA4 = LNKCAP2        (链路能力 2) ← 支持速率向量
       0xA8 = LNKCTL2        (链路控制 2) ← 目标速率
       0xAC = LNKSTA2        (链路状态 2)

2.2 0x88084 LNK_CAP（链路能力）

位  字段  值  实测（Gen1 态 / Gen2 态）
[3:0]  SPEED  1 = 2.5 GT/s，2 = 5.0 GT/s，3 = 8.0 GT/s  1 / 2
[9:4]  WIDTH  最大链路宽度  4 / 4（★ 这张卡就是 x4）
[11:10]  ASPMS  ASPM 支持  0
[14:12]  L0SEL  L0s 退出延迟  1
[17:15]  L1EL  L1 退出延迟  1 / 2
[18]  CLKPM  时钟电源管理  1
[19]  SDERC  Surprise Down 错误报告能力  0
[20]  DLLLARC  DLL 链路激活报告能力  0
[21]  LBNC  链路带宽通知能力  0
[31:24]  PORT  端口号  0

整字实测：0x00463C41（Gen1 态） / 0x00454C42（Gen2 态）
（差别主要在 SPEED 与 L1EL，与链路实际状态联动）

2.4 0x88078 EXP_HEAD（PCIe 能力头）

位  字段  值  实测
[7:0]  CAP_ID  0x10 = PCIe  0x10
[15:8]  NEXT_CAP_PTR  下一个能力指针  0x00
[19:16]  VERSION  PCIe 能力版本：1 = v1 模式，2 = v2 模式  1 / 2
[23:20]  TYPE  0 = Endpoint  0

整字实测：0x00010010（v1 模式） / 0x00020010（v2 模式）。
★ 这个版本字段在真实硅片上通常是硬连线的，本卡却能随状态在 1/2 之间变化 ——
它是"设备处于 PCIe v1 还是 v2 模式"的直接标志。

2.5 0x880A4 LNKCAP2（链路能力 2）

⚠️ 该寄存器在公开寄存器定义（envytools rnndb）里没有定义，语义按 PCIe 规范推断。
另：该地址在社区逆向资料里被称为 LINK_CAP2。

位  字段  值  实测
[7:1]  SLSV  支持速率向量：bit1=2.5、bit2=5.0、bit3=8.0 GT/s  0b001(0x02) / 0b011(0x06)
其余  保留  —  0

整字实测：0x00000002（只支持 Gen1） / 0x00000006（支持 Gen1+Gen2）。
Gen3 需要 0x0000000E（三个位全置）—— 从未在本卡上出现过。

2.6 0x880A8 LNKCTL2（链路控制 2）

位  字段  说明  实测
[1:0]  SPEED  目标链路速率。rnndb 原文注释："0 is used when the card is in v1 mode, 1 in v2+ mode"；2 = 5.0 GT/s，3 = 8.0 GT/s  0 / 2

整字实测：0x00000000（v1 模式、目标速率未设） / 0x00000002（目标 5.0 GT/s）。
★ 写 3 会被硬件钳回 2（或写成后被立即读回为 2） —— 这是 Gen3 不可达的核心现象。

2.7 0x8841C CONFIG（能力字段生成器输入）

这是本卡上唯一"写它就能改变配置空间能力声明"的寄存器。
官方定义见 rnndb：reg32 offset="0x41c" name="CONFIG"（G84- 起）。

位  官方字段名  说明  实测行为
[8]  AER_EN  AER 使能  未测
[10]  UNK600_CAP_EN  VSEC 0x600 能力使能  未测
[12:11]  GEN2_DIS  官方注释："Set to 3 to disable gen2"  ⚠️ 与实测不相关（见下）
[14:13]  （无文档名）  ★ 实测的 Gen2 降级门：== 3 时声明被强制降为 0x02  ✅ 实测有效
[15]  （无文档名）  ★ "L 的置位者"：复位前置 1 → 复位后声明锁存为 Gen2  ✅ 实测 7/7 无反例
[17]  MSG_CAP_EN  消息能力使能  实测：清 bit17-23 会改变 LNK_CAP 的 bit18
[18]  CLKPM  官方注释 "goes to EXP_LNK_CAP"  ✅ 实测吻合
[21:19]  L1_LAT  官方注释 "goes to EXP_DEV_CAP"  文档定义
[23]  INTR_ROUTE  中断路由  未测

整字实测：

冷启动 / Gen1 态（复位未预置）  0xC0B46500
Gen2 态（工具/复位预置后）       0xC0B5AD00、0xC0B58D00 等
门关闭（强制 Gen1）              0xC0B5ED00

★ 重要发现：官方文档把 GEN2_DIS 定在 [12:11]，但实测真正起作用的门在 [14:13]
（官方字段与声明变化不相关：有的状态 [12:11]=1 却声明 Gen2，有的 [12:11]=0 却声明 Gen1）。
⇒ 文档的位偏移可能不准（差 2 位），或者存在两个相似字段。

2.8 0x2241C PUNITS.PCI（live 的 Gen1/Gen2 选择器）

来源  名字  字段定义
envytools rnndb（punits.xml，PUNITS 基址 0x022400，+0x01C）  PUNITS.PCI  PCIE_VERSION bit0：0="1"，1="2"；PCI_CLASS bit1；PCIE_SPEED bit7：0="2_5GT"，1="FULL"（注释：5 or 8）
社区逆向（GA100 平台）  NV_PTOP_FS4  bit0 = GEN2_PCIE，bit7 = GEN2_PCIE_SPEED

本卡实测：

0x00000000  →  声明 0x02、目标速率 1、LNK_CAP 最大速率 1     （Gen1 模式）
0x00000081  →  声明 0x06、目标速率 2、LNK_CAP 最大速率 2     （Gen2 模式）

★ 它是主机可写、且写入后【立刻生效、不需要复位】的：
写 0x00 声明立刻降为 0x02，写 0x81 立刻回到 0x06。
在两个文档化位里没有 Gen3 编码 —— 这也是"输入字母表只有两档"的出处之一。

可访问性：该寄存器所在的 0x022000 区块里，邻居寄存器返回特权毒值，而它本身可读写
（说明这是设备有意向主机开放的一个配置点）。

3. 熔丝（fuse）：那堵墙的正面
------------------

3.1 地址映射【实测】

社区资料使用的是"priv 地址"（0x82xxxx），本卡 BAR0 里的对应地址是：

priv 地址 - 0x7FF000 = BAR0 偏移
  例：0x82057C → 0x02157C        0x82580 → …（同理）

3.2 三个代际相关熔丝的实际值【实测】

熔丝  community 地址  本卡 BAR0  实测值  含义
GEN23_DIS  0x82057C  0x02157C  1  Gen2/Gen3 被禁用标志
GEN3_DIS  0x820580  0x021580  1  Gen3 被禁用标志
LANE_DIS  0x820394  0x021394  0  通道禁用标志 = 干净（宽度不是被熔丝关的）

判定：这三个值是只读熔丝回显【实测】——
在 5 份 dump、700 个可读点里恒定不变（0 个变化点）。
唯一文档化的熔丝读取控制位（PUNITS.FUSE_CONTROL bit11，地址 0x022400）写不进去。

外部一致性：同类卡（CMP 170HX，GA100 平台）在同一组地址读到的是
GEN23_DIS=1 / GEN3_DIS=1 / LANE_DIS=0 —— 三值完全相同。
他们用完全不同的方法（安全协处理器级写入）也只做到 Gen2。强支持

3.3 PFUSE 区可读性【实测】

BAR0 0x021000 - 0x021FFF：675 个可读 dword
  其中大部分是显存/单元配置、温度校准、单元禁用掩码等
  rnndb 的 pfuse.xml 只定义了 7 个字段（TPC/PART 禁用掩码、温度校准、SPEEDO）
  ★ 没有任何“PCIe 速率/代际”的覆盖/影子字段

5. 三条 live 通路与 8 组矩阵
--------------------

5.1 通路

通路  地址  机制  是否需复位
A  0x8841C[14:13]  == 3 强制降级为 Gen1  否（live）
B  0x8841C[15]  复位前置值：复位前置 1，复位后锁存 Gen2  是
C  0x2241C[7]  写 0/1 立刻切换 Gen1/Gen2  否（live）

5.2 完整矩阵【实测】

LTSSM(0x8872C)   0x8841C[14:13]   0x2241C[7]   →   声明(0x880A4)
     6                 0               1        →   0x00000006   ★ 唯一 Gen2
     6                 0               0        →   0x00000002
     6                 3               1        →   0x00000002
     6                 3               0        →   0x00000002

6. 毒值（sentinel）速查
-----------------

设备对特权保护或不存在的地址返回固定错误码。这些值不是数据。

值  含义
0xBADF5040  特权违规（读被遮挡，写不落地）—— 最常见
0xBADF1100  PRI 毒值 / 该地址在此上下文不存在
0xBADF1201 / 0xBADF1301  同类变体（不同区块）
0xBADF1701 / 0xBADF1705 / 0xBADFBADF  同类变体
0xBADF5108 / 0xBADF510C  安全特权掩码的 PL0 读取
0xBAD00100 / 0xBAD00200  同类变体
0xFFFFFFFF（整片）  BAR0 映射已失效（卡掉下总线）
0xDEADBEEF / 0xDEADDEAD  ★ 转储工具自己写的"读失败"填充值，不是硬件值

建议规则：任何 0xBAD????? 一律视为"该地址在此上下文不可访问"，不要逐个列举。
★ 注意：0xBADF5040 的 bit31 = 1 —— 不要把它误读成"某个使能位 = 1"。

7. 覆盖率地图（诚实边界）【实测】
------------------

BAR0 0x000000 - 0x0FFFFF（1 MB = 262,144 个 dword）：
  能读到真实值的 dword         61,573  （23.5%）
  按“整页全可读”的严格口径      25 / 256 页 ≈ 1.9%
  其余地址                      返回毒值

BAR0 0x100000 - 0x1FFFFF（1 MB）：
  在全部转储里都是填充值，没有任何寄存器数据 ⇒ 本项目不对该区作任何结论

⇒ 准确说法："扫描了设备向主机开放的 23.5% 的 dword"，不是"扫过全部 BAR0"。
（项目早期曾把"全 BAR0 扫描"当作结论强度的一部分，这是不准确的，已在 03-走过的弯路.md 更正。）

8. ★ 危险操作清单（血换来的）
-----------------

禁止  原因（实测后果）
对 0x8C040（LINK_CONFIG_0）做逐位写走查  本项目实测：显卡掉下 PCIe 总线，只能重启恢复
对含 COMMIT / 使能 / 复位语义的寄存器做逐位走查  同上，这类寄存器每一位都可能触发硬件动作
用 taskkill /F 强杀持有显卡驱动的进程  驱动进入不可恢复状态（卸载脚本的特殊场景除外）
一次会话内整卡复位超过 2–3 次  本项目一次会话内做过 9 次，属于超限操作，不应效仿
在"按住进程"运行时做寄存器实验  常驻进程每 ~20 ms 回写，会污染测量结果
不做对照写入就下"只读"结论  写通道本身可能坏了（本项目踩过，见 03）
为 Gen3 刷 VBIOS / 为 x16 焊电容  收益已被证明为 0，风险不可逆

出问题时的恢复顺序：① 停止常驻进程 → ② 还原寄存器（-off）→ ③ 重启 → ④ 仍未恢复则重装驱动。

9. 手工复现（不依赖工具）
--------------

9.1 用工具读（最简单，无需管理员）

status.cmd
:: 会打印 LNKSTA / LNKCAP / LNKCAP2 / 带宽等原始证据
:: 完整寄存器细节：以管理员身份运行  bin\P104Gen2x4.exe -diag

9.2 判定公式

判据  公式  通过条件
当前速率  (LNKSTA >> 0) & 0xF  Gen2 = 2，Gen3 = 3
当前宽度  (LNKSTA >> 4) & 0x3F  本卡恒为 4
支持速率向量  (LNKCAP2 >> 1) & 0x7  Gen1+2 = 3，含 Gen3 = 7
带宽  H2D / D2H 实测  Gen2 x4 ≈ 1.55 / 1.69 GB/s

9.3 复现"Gen3 被端点拒绝"（需要能写 PCIe 配置空间）

① 确认当前是 Gen2 稳态：LNKSTA[3:0] == 2，带宽 ≈ 1.55 GB/s
② 找到 PCIe 能力结构基址（配置空间 0x34 → 链表，找 Cap ID = 0x10）
③ 写 LNKCTL2（能力基址 + 0x30）的 [3:0] = 3
④ 立刻回读 → 仍然是 2（被钳回）
⑤ 同一时刻写上游根端口的 LNKCTL2[3:0] = 3 → 回读 = 3（根端口接受）
⑥ 持续 25 秒反复写（每 5 ms 一次）→ 仍全部被钳回；LNKSTA 始终不变成 3
